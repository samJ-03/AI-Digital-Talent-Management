# 已获授权的修正设计

依据：用户明确要求按现有14项审查意见修正，并授权一期仅保留核心，其余由执行者移二期。这是对既有评审的实施，不要求用户重复确认同一方向。

选择：保留现有技术栈与已验证能力，仅做有确定收益的小改；不推倒目录、不删历史表、不重建任务框架。另一方案是全量DDD/通用索引重构，会增加风险且无一期收益，因此不选；只改文档而保留已确认的多余图执行和私有跨模块依赖，也不足以处理已完成内容。

一期：组织账号、岗位条件/发布试卷、文本PDF/DOCX导入、人才库基本查询/修订/去重、共享画像、三态硬筛/人工覆盖、岗位匹配、唯一邀考、候选人核验/答题/交卷、成绩复核与HR招聘决定。基本配置可以受控CLI初始化并供最小管理表单维护，详细美化/仪表盘不阻塞G1。

二期：OCR/MinerU/旧DOC、高级语义检索界面与rerank、知识问答、AI出题、复杂统计/报表、培训（含展示页）、部门负责人协作、通用编排/微服务扩展。T20已实现后端保留为可选能力，不作为一期匹配或验收的强制依赖。

已完成代码修正：FixedGraphRunner保留调用接口但直接走受控网关，不再构建单节点StateGraph；服务公开最少量resume_view/is_current/resource_scope接口；评估详情match统一dimensions字段；禁止改变权限、来源、评分或租约语义。新代码以RED/GREEN及完整回归证明。

文档：原完整计划归档；09成为精简且可执行的一期计划，T编号不重编号、部分任务用a/b拆分，完成项引用证据。02/03/08只管架构决策，10只管实际导航，handoff只保留一个当前检查点。04与05与现行schema对齐，当前评估受理即切current明确。T30只验收既有流水线，不新造中央resume_pipeline。T34明确专属知识索引、二期再做。

契约检查：新增轻量OpenAPI导出和manifest检查，区分已实现、一期待做、二期延期；不能以固定104计数作为成功。原语义基线仍可追溯，类型从实际schema生成。已完成代码和一期接口都受检，不把未实现条目伪装绿。

一期不新增LangGraph执行依赖；锁文件暂保留既有安装包以减少无关依赖升级。Milvus保留现有服务定义和数据，但默认启动置semantic可选profile；完整T20回归需显式启用，不删除任何容器/卷。

模型/真实邮件保持现有授权边界，常规回归仅受控合成供应商。质量、安全和恢复门跟随核心，不等二期全功能后再执行。输出继续保存Obsidian项目，代码按既有授权提交上传。
