## 3. 推荐使用方式

主栈选型见03。保留Python/FastAPI/SQLAlchemy/MySQL方向；前端采用Next.js/TypeScript；语义人才库采用Milvus，文件MinIO，Redis队列/会话。项目专用Linux容器运行Celery/OCR等，避免Windows原生worker的不支持问题。已有MySQL可作为候选，必须新库、新账号，禁止使用旧项目业务库进行试验。

Node版本数字已满足当前Next.js官方最低20.9要求，但实际运行与锁文件仍须验证；依据：[官方安装指南](https://nextjs.org/learn/react-foundations/installation)。Celery官方说明不支持Windows，因此选择Linux执行：[官方支持说明](https://docs.celeryq.dev/en/stable/getting-started/introduction.html)。Milvus的Windows方案要求WSL2与Linux容器：[官方部署指南](https://milvus.io/docs/install_standalone-windows.md)。这些是技术建议的依据，不是本机已运行证明。

## 4. 开发前必须补证的条件（不是本轮开发todolist）

1. 命令执行环境恢复，实际确认Node、Python、Git、Docker/Compose及WSL2；不得绕过权限限制执行。
2. 创建专用环境后安装锁定依赖，验证可导入、可构建；浏览器安装供后续E2E测试。
3. 以项目专用服务名/端口启动MySQL或独立库、Redis、Milvus、MinIO，记录健康检查和SDK真实读写；不只探测TCP。
4. 模型网关实际完成结构化提取、出题、评分与Embedding；固定模型digest、embedding维度、提示词版本。小模型不达质量目标时选择更合适模型并重新评测，不直接降低标准。
5. 测试环境邮件收件箱真实接收；生产需企业SMTP、发件授权与外部HTTPS考试地址。当前均未配置和验证。
6. OCR/旧DOC转换实测，准备字体、模型权重和超时沙箱；CPU解析的并发和内存需测量。
