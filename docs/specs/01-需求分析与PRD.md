## 2. 目标、对象与问题

帮助 HR 将外部简历变成可检索、可复用、可追溯的人才资产，按岗位粗筛和语义匹配自动邀考，再由 HR 综合证据作出选人决定。解决人工整理简历重复、资料分散、岗位匹配依据不清、考试组织繁琐、历史人才无法复用等问题。

C：一家企业内部使用，多个部门与 HR；所有人才是外部候选人。无企业注册、多租户计费、在职员工培训管理。AI 提供招聘辅助，岗位邀请线是考试邀请条件，不是录用线。

成功场景：HR 发布岗位与试卷、开启自动邀请，导入一批简历；系统解释粗筛结果，生成画像及岗位匹配，符合规则者收到岗位考试邮件；候选人答卷后，客观题自动评分、主观题待 HR 复核；HR 选人并跟踪至录用或结束。

## 3. 角色与权限

| 角色 | 职责 | 不应获得的权限 |
|---|---|---|
| 管理员 C | 账号、部门、角色授权、模型、提示词、固定 AI 流程启停、系统运行日志 | 默认不读取简历、答卷、HR 评价，不参与选人 |
| HR C | 岗位、导入、人才库、画像、筛选、题库试卷、评分复核、招聘状态 | 模型密钥和账号权限配置 |

D：HR 的基础人才库在企业内共享；岗位、应聘记录、考试、评价按岗位所属部门授权。HR 对共享人才仅查看基本履历与来源，不借此读取其他部门私有评价、试题或考试详情。跨部门已正式结果只展示“存在历史记录”，详细内容须额外岗位授权。管理员的技术权限不自动等于 HR 数据权限；演示使用两个独立账号。可配置角色授权，所有请求后端校验，不能只隐藏菜单。

## 5. 业务主线与规则

### 5.1 岗位准备

HR 新建岗位草稿，设部门、职责与岗位相关要求、招聘人数；结构化条件分 required/preferred。发布岗位条件和试卷后，设置匹配邀请线、邀请有效期、答题时长、邮件模板，最后开启自动邀请。关闭或暂停岗位立即阻止新的自动邀请。修改正文可保存草稿，发布产生新版本。

D：主筛字段为学历、专业、相关工作年限、技能/证书。学历需明确最高/全日制等口径，默认最高已取得学历；专业使用可维护词典与别名，模糊映射进入待核实；重叠工作时间不重复累加。年龄不作为默认自动邀考筛选项；若业务确需启用，须 HR 明确岗位依据并人工复核，不能由姓名/照片推断。性别、婚育、健康、民族等不进入匹配评分。此为设计建议，不宣称法规结论。

### 5.2 导入与身份确认

HR 选择一个岗位导入（C）；可在人才库模式导入而暂不指定岗位（D，沿用早期讨论），此时只建档不自动邀考。每份文件独立处理，一份失败不回滚整批。拒绝危险或超限文件，失败需可见原因。

解析成功即形成 provisional 人才档案，含原始文件、提取结果和字段来源；缺邮箱标记 pending_email，允许留库和修正，禁止自动筛选/邀考，补齐有效邮箱后继续。邮箱必填是进入招聘自动流程的要求，不是要求 HR 上传前肉眼确认文件内容。无法解析的文件停留导入队列，不伪造完整档案。

重复文件哈希命中可复用解析产物；邮箱/电话相同或身份冲突只提示疑似重复，不仅凭相似向量/同名自动合并。待确认重复阻止新自动邀请。HR 确认同人后绑定同一候选人并保留简历版本；明确不同人后保留独立档案。人才与岗位唯一应聘关系，重复导入不重复建应聘记录。

### 5.3 粗筛和人工处理

每个硬条件输出 met/unmet/unknown 及原文依据。任一 required 明确不符，则总体不符；无不符但有 unknown，则待核实；全部满足才通过。preferred 只影响匹配展示，不造成硬拒绝。AI 不直接决定学历和年限硬条件；由已提取/人工确认的结构化值与规则引擎比较。

HR 可以有理由覆盖粗筛或手动邀请，保留原始结果、操作者、时间与原因。缺有效邮箱、岗位关闭、试卷不可用等技术前提不能被“人工覆盖”绕过。未通过仅对当前岗位生效，不删人才、不标记全局“差人才”。

### 5.4 画像与匹配

人才画像页面由共享履历画像＋有权限的岗位考试/评价视图组成。共享画像及其向量只融合简历和明确共享的事实，不融合部门私有评价，防止摘要间接泄露；岗位适配优势/缺口属于该岗位的匹配记录，在画像页切换岗位查看，不能污染通用画像。AI 归纳须关联简历段落、试题/正式成绩、面试评价，标明“简历自述/AI 归纳/HR 确认”。没有考试和评价时显示尚无数据，不生成虚构雷达分。

匹配采用版本化评分规则，分数是匹配建议而非录用概率。仅有投递岗位或 HR 指定岗位进入自动处理；系统推荐其他岗位后须 HR 加入流程，禁止向所有岗位自动群发。AI 无法生成可靠结果则待复核，不能默认 0 分或 100 分。

### 5.5 自动邀请与考试

自动邀请条件同时满足：岗位开放且开关启用、有效邮箱、去重确认完成、粗筛通过、匹配成功且达到邀请线、岗位发布试卷有效、未存在本轮考试邀请、应用未结束。发送前再次检查开关及状态，落库后异步发送。

邀请冻结岗位版本、筛选匹配记录、简历版本、试卷版本、邮箱与时间策略。邮寄成功仅表示邮件服务接收，不等于候选人已读。超时不确定发送进入待核对，不无限重发。邮件无效/失败进入 HR 待办。

候选人独立页面核验邮箱控制权后建立仅限本人考试会话；不接入后台账号。邀请截止限制开考时间，开考后按冻结时长计时；两者分开。答题自动保存，由服务端计时，到时自动提交最新已保存答案。网络中断可恢复同一答卷。发送中状态只保存在通知记录；暂停取消未发邮件时邀请置revoked，再开启不自动复活。重新邀请须 HR 明确操作，新考试轮次与历史并存，不静默覆盖。

### 5.6 评分与招聘决定

固定题型第一版为单选、多选、简答；客观题规则随卷冻结，多选默认全对得分，其他为零（D）。主观题依据冻结参考标准，AI 提供建议分、依据与不确定项；HR 复核后发布正式成绩。全客观卷可自动形成正式成绩。AI 失败不阻止客观计分，主观部分转人工。

HR 分别查看粗筛、岗位匹配、正式考试分和评价，自主推进或结束；无自动淘汰、自动录用。面试记录为 HR 手工记录，不实现线上视频面试。候选人端仅展示提交状态，不自动公开分数、答案或评价。

### 5.7 人才复用及版本变化

新增岗位可从人才库筛选/语义搜索/推荐人才，HR 选中后创建该岗位应聘记录，再走新岗位规则。已有考试成绩可作为可见历史参考，默认不直接替代新岗位考试。

岗位/简历/画像变化不覆写已有筛选匹配快照；HR 发起重新评估，新结果标记当前，但保留历史。重新评估不自动再邀考。取消、关闭岗位后的重开由 HR 明确发起。

## 6. 状态模型（业务口径）

不能把导入、粗筛、考试与录用全部挤进一个 status。

| 对象 | 主要状态 | 终止/恢复 |
|---|---|---|
| 导入文件 | uploaded → queued → parsing → parsed / failed | 失败可重试，保留错误 |
| 人才资料 | pending_email / duplicate_review / ready / archived / merged | 补齐或确认恢复；归档停止自动处理 |
| 应聘评估 | pending → screening → needs_review / screened_out / matching → matched / evaluation_failed | 人工覆盖或重评创建新记录 |
| 邀请 | pending → sent / delivery_failed / delivery_unknown；revoked / expired | 重发同邀请；新考次须新轮次 |
| 答卷 | not_started → in_progress → submitted → grading → pending_review → finalized | 全客观可跳过复核；断线恢复原卷 |
| 招聘阶段 | evaluating → assessment → hr_review → interview_pending → interview_passed → offer_pending → hired | 任一适用阶段 HR 可 rejected/withdrawn；所有流转留痕 |

考试超时由答卷状态表示，不自动认定招聘不通过；不参加考试记录 no_show，HR 决定后续。自动完成评分不等于面试通过。

## 8. 指标与验收原则

核心上线门槛：本稿主线真实数据闭环；P0 核心、权限、计时与幂等用例全部通过；P1 重要功能全部通过；P2 有记录且不影响主线。明确取代旧资料“P1≥95%”与“P0/P1全绿”冲突。单元测试允许受控替身，最终业务验收必须真实 MySQL/向量/对象存储/模型/测试邮件链路。

业务计数：人才按合并后的候选人去重，应聘人数按岗位关系；简历份数与人才人数分开。岗位缺口=max(需求人数-已录用人数,0)，同时另列已到岗人数（仅未来接入）；绝不能按匹配推荐人数推算缺口。正式平均分只统计 finalized，缺数据记为未产生，失败不记零。

性能初始方案 D：演示基线 1 万人才、20 个活跃 HR、50 个并发考试；普通列表 p95≤1s、仪表盘 p95≤3s、自动保存 p95≤1s，AI 长任务异步展示进度；向量检索目标 p95≤500ms（不含模型推理），需实测。原资料 2000 在线、可用性99.9%、解析99%/检索95%/匹配90%作为保留的扩容/质量目标，尚未证实；调整验收规模必须随本稿由用户审阅，不能用本机演示等同生产达标。准确率定义、样本和证据见 06。
