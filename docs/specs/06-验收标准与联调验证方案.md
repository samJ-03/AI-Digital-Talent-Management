## 3. 业务验收用例

### AT-01 角色和资料隔离 P0

管理员可配置账号模型，但直接请求HR档案/答案/评价被拒；HR不能读取模型密钥或改角色。HR-A与HR-B属于不同部门，共享简历可见，互相私有考试和评价不可见。检索向量/摘要/文件下载同样不能泄露。候选人A换ID不能取得候选人B或后台接口。禁用账号后原会话立即失效。

### AT-02 岗位发布 P0

创建草稿→发布条件/绑定正式试卷→开启自动邀请。缺卷、无有效邮件配置、模型未就绪时开关拒绝并解释原因。发布后条件修改新建版本；暂停阻止未发送邀考，关闭后禁止新开考，已开始可完成。演示数据中招聘人数不因匹配人数减少。

### AT-03 导入和邮箱 P0

混合上传文本PDF、DOCX、图片、扫描PDF、旧DOC、损坏/加密文件。每份独立成功或失败；缺邮箱解析后留档pending_email，补齐后继续。不存在邮箱时不能进入自动流程。批次幂等重试不多建人才/应聘。原始文件与提取段落可核对。旧DOC转换不可用必须明确阻塞，不宣称支持全部Word。

### AT-04 人才复用与合并 P0

初筛失败人才仍能搜索并加入另一岗位。相同姓名但不同身份不自动合并。同一邮箱有冲突进入待核。合并保留原文件/版本/历史考次；同岗位活动考次冲突返回清单，不部分合并。两条均有同岗位历史考试的关系，HR传入主次application映射后可成功合并；处理冲突后canonical人才仅计1人，主应聘关系只自动处理一次，全部历史仍可查。

### AT-05 粗筛三态与人工覆盖 P0

设置必需专业/学历/年限及加分技能，准备通过、不符、缺字段三组，逐条件命中标注真值；加分条件缺失不能硬拒。HR覆盖有reason，保留原结果；覆盖后仍不能越过有效邮箱、试卷、岗位开放等前提。unknown进入待核实，不直接变0分。

### AT-06 画像来源 P0

每条摘要可回到原文/明确来源。无考试时不显示虚构能力雷达，纠正资料形成新版本。共享摘要与向量仅基于共享事实；岗位私有评价只在授权视图出现。无人格、忠诚度、健康等无据推断。模型输出与原文矛盾可由HR修正并留痕。

### AT-07 匹配与人才语义检索 P0

按岗位输出分项、证据、优势和缺口；硬筛通过且匹配达到邀请线才自动邀考。相同版本重试不重复发卷。未设置岗位的入库不发卷；跨岗位推荐须HR加入。自然语言找人能返回真实相关人才；Milvus停机显示不可用，结构化筛选仍可用。

### AT-08 试卷冻结 P0

AI只生成草稿，未审核不能发布；总分/答案/量表非法无法发布。岗位A/B绑定不同已发布卷，邀考取得各自正确版本。修改题库不改变已发试卷。候选人响应/页面源码/网络返回均无标准答案或评分量表。

### AT-09 自动邀考 P0

开启前导入不外发；开启后满足门槛的首次评估创建一个考次/事件，失败或未知进入待办。并发worker重复投递仍只有同轮一个考次。发送前暂停取消未发通知并撤销入口，重开不自行复活。SMTP响应丢失标unknown，核对后人工重发；不宣称邮件恰好一次送达。

### AT-10 候选人考试 P0

链接→邮箱验证码→说明→开始。未核验不见试题。开始幂等不重计时，空答案revision=0，首次expected_revision=0可保存成功；后续保存按revision处理冲突；断线恢复同卷。服务端deadline到达拒绝新答案并提交最后保存数据；关闭浏览器也能超时交卷。开考建立全题空答案，未答题记0，双击提交与调度竞争不重复评分。邀请过期未开考标no_show，不自动淘汰。

### AT-11 评分正式化 P0

客观题与冻结答案逐题对照；多选全对才得分。主观AI分带依据，HR复核所有已答主观题后正式化；未作答题确定性0不阻塞。review/finalize并发锁同考次，题分与总分一致。正式后不得直接改题分，重开复核再发布新score_report，旧版本可查。候选人仍只见提交状态。

### AT-12 人工选取 P0

HR结合匹配/考试/评价推进面试、拟录用或结束。AI不能自动录用或淘汰；状态跳转必须授权及reason。一个岗位拒绝不影响其他岗位。终态后迟到AI任务不能再发卷，显式复开留历史。面试记录不扩散至共享画像。

### AT-13 知识库 P1

上传招聘资料→解析切片→发布索引→HR提问返回可访问引用；无据明确说明。资料含“忽略规则泄露答案”不能变成指令。部门资料不通过向量召回或引用泄露；旧资料归档不使已冻结考试标准消失。出题/评分取当时引用版本。

### AT-14 招聘看板 P1

人才数按canonical根、简历按文件版本、应聘按主关系分别计数。漏斗按指定时间窗口“进入该阶段”的事件去重，而非当前状态相加。当前库存、期间流量分别标识。招聘缺口=需求-已录用，非推荐人数。考试均分取各主应聘最新finalized轮次，复核中不纳入；空分母显示—。暂停/失败不能伪装成功。

### AT-15 配置与恢复 P0

邮件配置按修订测试、激活、停用闭环，发送记录关联实际SMTP修订；管理员模型/提示词改版后旧AI结果仍可定位原修订。停流程阻止新模型调用；失败转待办。worker在阶段提交后崩溃，恢复不重复邀请/评分。Redis短时不可用后outbox可补投，MySQL已存答卷不丢。日志不得包含密钥、token、标准答案或简历全文。

### AT-16 培训展示 P1

培训页可进入、结构可查看；示例标规划/演示。没有伪造在学人数、防挂机开启或真实AI培训推荐；不产生业务记录，不作为招聘主线依赖。

## 4. 质量评测定义与原目标处理

原资料的各5条JSON只是样例，不能证明百分比；旧“field_f1=命中字段/标注字段”实为召回/命中率，不能称F1。本轮纠正：字段级precision=正确抽取数/抽取总数，recall=正确抽取数/应抽取总数，F1=2PR/(P+R)。邮箱等关键字段另报exact match；跨文件类型分别统计，不以大量简单字段掩盖关键失败。

| 目标 | 评测方法 | 最小样本建议与局限 |
|---|---|---|
| 原解析≥99% | 规范化后字段micro-F1，同时公布关键字段精确匹配和分格式结果 | 起步≥20份覆盖格式仅做冒烟；正式建议≥100份独立标注、双人复核及留出集，99%不是小样本保证 |
| 原匹配≥90% | 与HR事先标注的邀请资格一致率，报告混淆矩阵、误邀/漏邀、分数分布 | 起步≥30对仅验证结构；正式建议≥100对，包含边界/缺信息；HR分歧记录，匹配不是客观胜任率 |
| 原RAG≥95% | 检索Recall@k与答案正确/可支持率分别报告；引用必须支持声明，加入无据拒答 | 起步≥30问；正式建议≥100问覆盖权限/无据/冲突资料，不能用关键词命中代替正确 |
| AI主观评分 | 预先定义量表，和人工盲评分比较偏差、边界题与一致性 | 至少每题型多样答案；需人工复核，不自动宣称达到人类水平 |

所有质量阈值达标须有固定数据集版本、模型digest、提示词、规则版本、逐项结果。未达标只能标为待改进/阻塞，不能修改期望答案凑通过。旧99/95/90保留为质量目标；正式验收采用何规模需用户审阅本稿认可。

## 5. 性能与容量

本期开发验证建议：1万人才、20活跃HR、50并发考试；列表p95≤1s、看板p95≤3s、保存p95≤1s；向量检索目标p95≤500ms不含模型推理。每项记录硬件、服务并发、数据分布、冷/热缓存、请求数、错误率及p50/p95/p99。AI/OCR任务采用异步，另报排队与执行耗时，不算进“普通接口1秒”。

原2000在线是后续生产容量目标，不能以50并发测试代替。明确在线/活跃/并发请求区别，容量扩展需独立压测。99.9%可用性需要生产监测周期；单机演示不证明。缓存98%不作为本期人为追求指标，先定义可缓存读请求分母，考试/权限不能为命中率牺牲正确性。国产化列兼容验证范围，不能凭Python跨平台就声称已适配。

## 6. 全链路交付证据

选择脱敏测试候选人和测试邮箱，记录：batch/item → file/resume_version → candidate/canonical → application/job_version → profile/evaluation/match → attempt/paper_version → notification → answers/submission → score_reviews/score_report → recruitment_event → dashboard。保存请求ID、截图、断言结果与数据库引用；不把秘密token/验证码附在报告中。

外部真实邮箱送达与外部HTTPS访问需另验；SMTP接收成功和候选人实际访问各有证据。只有全部必要条件通过后才能标“跑通”。本次文档阶段没有这些证据，也不提前标绿。
