# 数据库表与数据一致性设计

V1.0评审稿｜2026-11-04｜目标MySQL8 InnoDB。以下40张表为新需求设计，不是从旧源码实测，不是可执行迁移。批准后由SQLAlchemy模型与Alembic生成DDL，再核对OpenAPI。旧seed_data.sql禁止直接使用。

## 1. 存储职责与统一约定

MySQL保存事实、业务状态、版本及审计；Milvus仅保存可重建的语义索引；MinIO保存私有文件；Redis保存短时会话、验证码和队列，不作为答卷唯一存储。

全部表含：id BIGINT UNSIGNED自增PK；created_at/updated_at DATETIME(6)非空UTC；row_version INT UNSIGNED默认1用于CAS。API将id序列化为十进制字符串，避免JavaScript大整数损失。已发布业务快照/正式成绩/审计插入后不允许业务更新或删除；evaluation_runs、任务和考次是可变运行头，完成后输入结果冻结，后续人工决定另记事件；updated_at保留与created_at相同。业务时间服务端生成，前端按上海时区显示。字段没写默认值时不得隐式默认0或空串；未知用NULL。姓名等人工资料不以空字符串伪装完整。

外键除显式逻辑引用外均建立真实FK，ON DELETE RESTRICT，禁止级联删除历史；主要FK加索引。循环当前版本指针在建表后第二次迁移添加FK；建主对象时指针可空，插入版本后同事务更新。FK不能保证版本属于正确主对象，服务层事务校验＋测试保护。状态使用VARCHAR＋应用枚举与CHECK，不能自由字符串。可变对象更新要求If-Match/row_version；发布版本不可变。UK=唯一索引，IDX=普通索引。

utf8mb4；邮箱规范化单独字段（去空格、域名小写，保留原始值；不擅自去除本地部分点号/加号），邮箱字段索引用binary一致比较。文件SHA256不等于人员身份。结构化JSON必须有Pydantic版本schema，禁止把可查询关联ID只埋在无约束JSON里；主要关系仍用FK。

## 3. 表字段字典

### 1. departments — 部门

| 字段 | 类型 | 约束/含义 |
|---|---|---|
| name | VARCHAR(100) | 非空 |
| parent_id | BIGINT UNSIGNED | 可空 FK departments |
| status | VARCHAR(24) | active/disabled |

约束与索引：部门不物理删除，避免岗位引用失效。

### 2. users — 后台账号

| 字段 | 类型 | 约束/含义 |
|---|---|---|
| department_id | BIGINT UNSIGNED | 可空 FK departments |
| login_name | VARCHAR(100) | 非空 UK |
| password_hash | VARCHAR(255) | 非空 |
| status | VARCHAR(24) | active/disabled |
| auth_version | INT UNSIGNED | 非空 默认1 |

约束与索引：禁止明文/可逆密码；禁用时撤销Redis会话。

### 3. roles — 角色

| 字段 | 类型 | 约束/含义 |
|---|---|---|
| code | VARCHAR(50) | 非空 UK |
| name | VARCHAR(100) | 非空 |

| status | VARCHAR(24) | active/disabled |

约束与索引：内置admin/hr；业务权限按permission_codes显式授予，admin默认无HR权限。

## 4. JSON核心结构

- job_versions.conditions：[{key,field,operator,expected,required,alias_dictionary_revision}]；operator固定白名单eq/in/gte/lte/contains，禁止直接拼SQL；期望值类型由field schema约束。
- resume_versions.structured_data：{schema_version,identity,contacts,education[],employment[],projects[],skills[],certificates[]}；field_sources按字段路径保存{value_source,page,paragraph,quote,confidence,verified_by}。
- candidate_profiles.evidence / match_results.evidence：[{claim,source_type,source_id,locator,quote}]；不得引用其他候选人或无权限评价。跨实体JSON来源引用在写入时校验、删除时通过清理任务处理。
- paper_items.options：[{key,text}]；answer_key选择题为{correct_keys:[]}，主观题用rubric.criteria[{name,max_score,description}]及参考要点。候选人DTO绝不包含answer_key/rubric/reference_sources。
- exam_answers.answer：选择题{selected_keys:[]}；简答{text:...}。按题型校验，不允许HTML脚本、超长或未知选项。
- model_configs.capabilities：{text_generation,structured_output,embedding,context_limit,verified_at}；仅验证成功后启用业务。

## 5. 一致性与关键事务

1. 导入：file staged→对象上传确认→import_item queued＋任务/outbox提交。对象成功而DB失败形成孤儿文件，由定时清理超过宽限且无引用对象；不得删除仍被引用文件。
2. 建档：锁候选身份匹配候选集，创建简历版本并更新current指针，创建或复用application。待重复确认的档案保持停机门；不得先邀考再合并。
3. 重评：插入evaluation_run及条件明细、match结果；只有完成后CAS更新application.current_evaluation_id。旧任务完成时不得替换更新版本已生成的结果。
4. 邀请：锁application及当前岗位，校验全部门槛，唯一application+round插入attempt＋notification/outbox，再更新招聘阶段与event。并发重复请求返回既有考次，不重复写外发事件。
5. 考试：start锁attempt；首次写server时间和deadline，并为冻结paper_items全集建立空答案行。未作答客观/主观题提交时确定性记0并标记已处理，不让漏题逃过计分。save校验题目属于paper、归属、截止时间与revision。submit与timeout走同一服务事务，只有首次冻结成功者创建评分事件。
6. 评分：逐题结果幂等写入；review与finalize均先锁同一attempt；主观复核append score_reviews，更新工作态answer最终分；finalize按paper_items全集确认答案行齐全、所有已答主观题复核完成，服务端求和写final_score，生成不可变score_reports并更新current_score_report_id，审计记录。正式后禁止直接review，先reopen-review变pending_review，保留旧报告；再次finalize生成新报告，统计只纳入state=finalized的当前报告。禁止客户端传总分。
7. 合并：锁两个canonical candidate根并校验无环，保留resume/profile/application/attempt原始candidate_id及版本号，不物理迁移历史。candidates.merged_into_id形成身份别名；查询按根聚合。重叠岗位由HR选择主application，次关系relationship_state=merged且canonical_application_id指主关系，历史考次保留原归属并在主视图按权限展示；活动考次冲突先返回MERGE_CONFLICT并由HR处理，未完成处理不得部分合并。自动动作只操作主关系。所有新建application/考次先锁canonical人才根，再查根及别名下既有岗位关系，复用主关系；原始UK(candidate_id,job_id)保留，根锁防止别名并发创建重复关系。
8. 招聘状态：有权限HR提交reason＋expected_version，合法状态表校验，更新stage和ended_at，追加event与审计；异步任务读终态后不得推进。

## 6. 状态流转约束

岗位draft→open→paused/closed，paused可open；closed重开必须HR显式动作。应聘evaluating→assessment→hr_review→interview_pending→interview_passed→offer_pending→hired。HR可带理由跳转至后续非终态（如无需考试直接面试），不得绕过活动考试事实；任一非终态可rejected/withdrawn。终态复开须专门reopen动作，旧事件不删除。

同一application多次evaluation、多个round；当前round递增只在HR批准新考次时发生，自动邀请不自增。邀请过期且未开考状态变no_show；已开考不因valid_until到达而停止，只看deadline_at。revoked未开考禁止换会话/开考，已开考撤销需HR明确取消考试并保存原因（第一版可不开放取消活动考次接口）。

## 7. Milvus与Redis设计

Milvus collection按embedding_config及维度隔离；人才向量对应profile版本，知识对应chunk，岗位对应job_version。字段为vector_key、entity_type、entity_id、candidate_id/job_id、scope、department_id、model_config_id、content_hash、embedding FLOAT_VECTOR(D)。D从实际模型探测，常见bge-m3维度不可凭名称硬编码。索引与距离度量在验证时冻结，召回后MySQL权限复核。默认top_k与阈值可配置，返回“语义相关”而非“必定胜任”。

Redis键：session:staff:<opaque_id>、session:exam:<opaque_id>、verify:<challenge_id>、rate:<scope>:<key>、celery队列。验证码哈希/错误次数/TTL原子更新；会话过期与禁用撤销。答卷每次保存写MySQL，Redis清空后不得丢失已保存答案。

## 8. 数据生命周期与容量

第一版无培训执行表、内部员工表、薪酬表、项目群/机器人表、多租户表。默认不存性别/婚育/健康/照片用于评分。档案原始文件可能含这些内容，访问受控；资料保留期按企业政策配置，上线前确定并实现到期清除，不能无限默认保留。归档停止自动流程，删除请求触发原文/向量/文件/AI产物一致清除并保留不含隐私的必要操作证据。清除是后续运行配置和受控动作，不在本轮实际执行。

1万人才示范规模下索引优先覆盖候选人检索、岗位阶段、任务待处理、超时考次。分页用稳定(id/created_at)排序；大数据后可游标分页。性能容量实测后优化，禁止为了旧“98%缓存命中”缓存试题答案或跨权限结果。
