# 一期总体架构与技术设计

2026-11-10。沿用模块化单体；一期只交付招聘主线。范围/状态见09，本文只定义职责、事务和恢复语义。

## 1. 架构与分层

Next.js页面经同域Nginx调用FastAPI。router只做认证依赖、DTO/请求头提取与响应；service控制权限、事务和业务编排；SQLAlchemy负责持久化；纯规则/scorer单独计算；外部模型/SMTP/MinIO用薄适配器。简单查询可以留service，复杂投影提取queries；不强制每表Repository、QuerySpec、BaseService或四层物理目录。

核心事实在MySQL，原件在MinIO，短期会话/消息在Redis。Celery执行任务，MySQL任务/Outbox保存执行权与交付事实，自建scheduler恢复租约和领域待处理事件。Milvus是已有可选人才语义索引，不是一期岗位匹配必经层；etcd只服务该可选组件。

## 2. 唯一业务责任

|领域|主要职责|不承担|
|---|---|---|
|identity|后台账号/组织/权限|候选人会话或招聘决定|
|ingestion|导入、格式解析/提取|邀考或录用判断|
|talents|规范身份、简历版本、共享事实画像、去重|部门私有评价混入共享事实|
|evaluation|三态硬筛、冻结评估、匹配/证据与查询|SMTP或考次创建|
|recruitment|人×岗位关系、HR阶段与面试记录|答案评分/通用任务编排|
|assessment|题库/卷、考次、候选人会话、答卷与正式评分|模型连接平台|
|notifications|SMTP配置、投递、unknown、重发交付|重新计算匹配或决定录用|
|runtime|任务/租约/Outbox交付与恢复调度|招聘状态机|
|ai_runtime|连接、提示词/输出契约、受控调用|邮件、正式成绩、录用写入|
|search（可选）|共享人才画像索引和召回|事实权威、知识部门权限|
|knowledge/reporting（二期）|资料专属索引/问答、统计口径|放宽人才共享索引保护|

查询归领域owner。已有IdentityQueries/RuntimeAdminQueries复用，不因任务编号较晚重新Create。跨领域使用公开resource_scope/is_current/resume_view等少量契约，调用方仍须授权；不通过公开工具类绕过权限。

## 3. 事务与当前性

一个业务命令的业务行、审计、幂等结果与持久任务/Outbox在同UoW提交。callback不能自行commit或另开Session。外部I/O在锁外，最终短事务复验当前来源/授权/配置/有效租约；失败可追加历史，不能推进新当前结果。

EvaluationRun在受理时冻结简历/画像/岗位版本、业务日期、规则修订、内容摘要，并在同事务切application.current_evaluation_id。它表示最新发起的评估，不表示最后成功的评估。新run pending/matching时旧高分只是历史，不允许替新run邀考。is_current还复验当前来源与岗位状态。旧记录上下文为空不可用今天口径重算。

模型给分项，服务端Decimal加权；无证据维度unknown，无总分，不以余弦×100当匹配分。人工继续保留原筛选结果与理由，设manual_only；技术门不能被业务例外覆盖。

## 4. 后台执行协议

短处理器接收(uow,job)并返回ResultRef/TerminalJobFailure。外部处理器prepare(lease)完成网络I/O，返回finalize(uow,job)，由JobRunner在有效租约事务内调用并提交。finalization_context可覆盖身份短锁，不能把模型或SMTP放入锁内。不要新增Callable[[job_id],ResultRef]的第二协议。

事件/任务生产者、消费者和去重键的现行唯一表见09第4节；T30只作注册补缺及纵向验收，不增加万能resume_pipeline。领域恢复器只判断本领域前提；runtime只交付/恢复租约。

## 5. 邀请、考试与正式成绩

岗位开关检查依赖就绪；人才处理检查邮箱/去重/来源；T22检查具体run、匹配、岗位卷和同轮唯一；SMTP发送前检查暂停/撤销及冻结邮件配置。这是不同时间点的必要复验，可共用纯谓词但不合并成万能EligibilityService。

考次创建与通知/Outbox原子提交；SMTP提交后接受不等于已读。明确拒收/接受/响应未知分开，unknown不自动盲重发。未开考显式重发可轮换token，保留考次、撤销旧token；原始token只在短期加密载荷，不进日志。

考试deadline由服务端冻结，开考有效期与答题截止分开；开始幂等，全题建空答案revision=0，保存CAS，手动提交与超时共用submit_once。客观题确定性评分，主观建议由HR复核；正式score_reports追加，重开复核不改旧报告。HR人工选人，模型无录用/淘汰工具。

## 6. 安全与一期部署

管理员与HR、候选人会话和DTO分离；共享简历不授权他部门答卷/评价；密钥仅私有环境与密文库，不输出。所有写动作有必要的幂等、版本和审计。MySQL/MinIO/Redis独立项目命名空间，测试只在talent_test。

核心Compose默认不启动Milvus/etcd；semantic profile保留可选功能与数据。不引入OCR、Dify、MCP业务运行、Kafka或微服务。生成执行是HTTPX受控网关的单次薄调用，不再编译单节点LangGraph；已有锁包暂不迁移，后续依实际多步需求再评估。

一期需要最小页面、受控初始化/干净启动/备份恢复、真实核心AI质量与竞争门；不是只做Swagger演示。生产HTTPS/企业SMTP/真实清除另按T43明确批准。历史全量部署图见assets，包含二期节点，不作为默认核心依赖清单。
