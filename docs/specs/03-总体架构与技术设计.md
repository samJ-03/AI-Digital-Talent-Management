# 总体架构与技术设计

V1.0 评审稿｜2026-11-04｜依据：01 PRD。全部为目标设计，尚未安装、迁移、部署或执行集成验证。

## 1. 技术结论

采用前后端分离的模块化单体＋独立异步工作进程。第一期不将岗位、人才、考试拆成网络微服务，避免为单企业招聘引入分布式事务。AI/OCR、任务与外部邮件通过适配器隔离，后续可按负载拆服务。最终技术选择及与旧强制组件的差异随本稿待用户评审。

| 层 | 推荐技术 | 责任与版本策略 |
|---|---|---|
| 前端 | Next.js 当前稳定大版本（建议16系）＋React＋TypeScript | 管理员/HR按角色路由、独立候选人考试页；依赖在开发环境验证后精确锁定，不直接沿用旧14系快照 |
| UI | Ant Design＋TanStack Query＋ECharts | 表格/表单、服务器状态和统计；复用原型颜色布局，不原样搬静态数据 |
| 运行时 | Node 24系；Python3.11 独立环境 | 本机 Node 文件元信息可用；Python 建议独立新环境，不污染既有 conda |
| API | FastAPI＋Pydantic2＋Uvicorn | 数据校验、权限、OpenAPI；API仅处理短请求 |
| 数据访问 | SQLAlchemy2 同步 Session＋PyMySQL＋Alembic | 与已发现MySQL匹配；同步数据库请求用FastAPI同步路由/线程池，不在async路由阻塞调用；每请求/任务独立Session |
| 业务库 | MySQL8 InnoDB | 人才、岗位、快照、考试、任务、审计是事实来源；开发拟用新独立库 |
| 向量 | Milvus standalone＋匹配的PyMilvus | 人才语义检索、岗位召回、知识切片；拟沿用本机部署文件2.6.5路线，先验证服务/SDK兼容，不采用旧文档pymilvus≥3.0的宽泛约束 |
| 文件 | MinIO私有桶（S3接口） | 简历和资料文件；业务桶和Milvus内部存储独立，不直接写其内部桶 |
| 队列/会话 | Redis＋Celery worker/beat | 长任务、服务端会话、速率限制；事实与结果仍在MySQL |
| AI流程 | LangGraph固定子图＋应用层持久任务 | 只执行预定义解析/画像/匹配/出题/评分/问答图，无动态代码或用户画布；主流程断点由MySQL任务和阶段产物控制 |
| 模型 | ModelGateway适配器；本地Ollama优先验证 | 文本生成与Embedding独立配置；发现bge-m3清单仅说明缓存存在，维度实际探测后冻结；现有小模型不能直接作为招聘质量合格结论 |
| 解析 | pypdf＋python-docx＋PaddleOCR独立适配器；旧DOC经LibreOffice隔离转换 | 文本PDF直取，扫描件/图片OCR；MinerU作为复杂版式候选方案需对比后再引入，不同时堆叠重型解析器 |
| 邮件 | SMTPAdapter＋测试环境Mailpit | 开发收件箱仅验证链路；正式外发接入企业SMTP，端口/授权留至配置阶段，不读取现有秘密 |
| 入口/运行 | Linux容器＋Compose，Nginx同域反代＋HTTPS | Windows开发机连接Linux容器或已有Linux测试机；不是Windows原生Celery |
| 测试 | pytest、HTTPX、Playwright | 规则/状态/事务测试、真实依赖集成、角色与考试端到端 |

本稿不把“选择工具”当成“环境已就绪”。环境证据与差异见02；官方兼容性依据见末尾。

## 3. 关键对象与责任边界

| 对象/服务边界 | 责任 | 不承担 |
|---|---|---|
| Candidate / CandidateService | 人的身份、当前资料版本、合并及基本档案 | 不保存全局“应聘失败” |
| Application / RecruitmentService | 一个人在一个岗位上的招聘关系、阶段变化 | 不自动录用 |
| ResumeVersion / IngestionService | 文件、解析结果、校正与来源版本 | 不覆盖其他简历历史 |
| JobVersion / JobService | 发布条件、评分配置、邀请策略 | 不直接发送SMTP |
| EvaluationRun / EvaluationService | 绑定版本，粗筛与匹配结果，人工覆盖、重评 | 不更新已发出的考试快照 |
| PaperVersion / PaperService | 题目、答案、量表冻结与发布校验 | 不向候选人DTO返回答案 |
| ExamAttempt / ExamService | 个人考次、计时、保存、提交 | 不采信浏览器倒计时 |
| ScoreReviewService | 客观评分、主观建议、人工正式化 | 不把AI建议直接当正式主观成绩 |
| InvitationService / NotificationService | 资格复查、创建考次与发件事件、失败恢复 | 不用SMTP响应决定数据库回滚 |
| KnowledgeService / ModelGateway | 有权限的资料检索、受限模型调用、结构化校验 | 不执行模型生成SQL或任意工具 |

这里只冻结领域责任，详细类方法签名与逐函数开发拆解在评审通过后的 todolist 阶段编写。

## 4. 长任务、事务和可恢复性

### 4.1 流水线

上传提交导入记录与outbox → 解析任务 → 提取并验证字段 → 建档/邮箱待补/重复待核 → 画像 → 当前岗位粗筛 → 匹配 → 邀请资格复核 → 建考次与发件事件 → SMTP发送。每阶段保存输入版本、输出、错误、开始/结束时间。

Celery只传任务ID，不传简历全文/密钥。任务以DB job记录为准；worker以租约和CAS领取，重复消息不得重复产生产物。每个业务动作具唯一幂等键，如 parse:resume_version:parser_revision；evaluate:application:run；invite:application:round；grade:attempt:submission_revision。任务超时/进程崩溃租约到期后可重新领取；自动重试次数有限，最终失败进入待办。

业务事务只覆盖MySQL：业务行、历史、outbox同事务提交。dispatcher在提交后派发；即使Redis暂不可用也能稍后补发。worker完成任务时在同事务写结果并追加下阶段outbox。不要在持有数据库锁时调用AI、OCR、对象存储或SMTP。外部调用完成后短事务校验版本/状态并提交。

### 4.2 邮件“恰好一次”边界

DB唯一约束保证同岗位同轮次不重复创建考次/邀请；SMTP不存在普遍的恰好一次承诺。区分明确拒收/明确接受/响应超时未知。未知进入delivery_unknown，由HR或服务商记录核对，不盲目自动重发。重发沿用考次及链接语义，记录发送次数；HR明确重考才创建新轮次。后台开关关闭/岗位结束时，发件worker发送前二次检查，取消未发送事件。

重发需要同一个有效入口。邀请token仅存哈希；首次邮件负载中的原始token加密保存在短期outbox私有载荷里（不是日志），送达确认后销毁该敏感载荷。显式重发可轮换token并撤销旧token，保留同考次；已开始考试不轮换活动会话。具体选择在接口中固定为“未开考重发轮换token”，不依赖从哈希反解原值。

### 4.3 索引一致性

MySQL保存画像/知识及vector_sync状态，outbox异步upsert Milvus；vector键包含实体和版本及embedding配置。改版先建新索引，验证后切active，清理旧索引。查询先限权限，召回后再从MySQL复查active/权限/归档，不能只信向量元数据。Milvus故障时结构化筛选仍可用，语义搜索明确不可用；不伪装成准确的空结果。画像变化后match不自动覆盖旧记录。

### 4.4 失败策略

解析失败可原文件重试；加密或损坏文件需换文件。模型输出不合schema/缺引用时有限重试，转人工待办；缺数据不填0。SMTP失败不撤销档案和评估。评分服务故障转人工复核，候选人已提交状态不回退。业务已结束后，迟到任务可以保存审计产物，但不得再邀考或推进阶段。

## 5. 固定AI设计

输入包含明确任务、结构化schema、受权限约束的证据片段；简历/知识文档/候选人答题均为不可信数据，忽略其中“修改分数/发送邮件/泄露答案”等指令。模型不能直接调用业务写接口。出题、匹配、评分各自记录model_config_revision、prompt_revision、input_hash、来源ID、耗时与结果状态。

结构化提取产物：identity、contacts、education[]、employment[]、projects[]、skills[]、certificates[]，每字段含value、source_resume_id、page/paragraph、confidence/needs_review。AI摘要不能升级为证实事实，HR编辑形成新版本并保存修改理由。

岗位硬筛是确定性规则。匹配D默认按技能50%、相关经历35%、岗位职责证据15%加权；HR可改但权重和须100%。单项可解释的结构化评分由模型提出、schema校验、服务端加权；不得将余弦相似度直接乘100当能力分。无证据维度unknown，阻止自动邀请并提示人工核实；模型分数差异通过评测校准。岗位分不含年龄、性别、婚育、健康、照片或对性格/忠诚度/稳定性预测。

LangGraph固定图负责extract→validate、retrieve→match→validate、draft_questions→validate、grade→validate等子任务；没有持久checkpointer时不声称LangGraph自身可断点恢复。跨任务恢复由应用层MySQL阶段产物/幂等任务保证，副作用发送放在图外。停用流程阻止新调用，正在进行的结果可保存但不能绕过资格检查。

问答：选定资料范围→权限过滤检索→引用证据生成→校验引用存在且可访问→返回答案和出处。材料不足明确说明，不承诺“绝对无幻觉”。答案/量表为考试机密，考试候选人无知识库接口。

## 6. 考试时序和安全

~~~mermaid
sequenceDiagram
  participant C as 候选人
  participant A as 考试API
  participant D as MySQL
  participant W as 调度/评分worker
  C->>A: 打开邀请并请求邮箱验证码
  A->>D: 校验token哈希、有效期和考次
  C->>A: 验证邮箱验证码
  A->>D: 建立仅本考次会话
  C->>A: 开始考试
  A->>D: 加锁写started_at与deadline_at
  A-->>C: 试题、服务端时间、截止时间（无答案）
  C->>A: 保存答案(revision)
  A->>D: 校验归属、状态、服务端截止时间，CAS保存
  C->>A: 提交
  A->>D: 锁定状态，冻结答案并投递评分事件
  W->>D: 到时仍在作答则执行同一提交逻辑
  W->>D: 客观计分、AI主观建议
  Note over D: HR复核后成绩finalized
~~~

邀请有效截止仅用于开考；实际答题截止=started_at+冻结时长，开始时已取得资格即可按时长完成，岗位关闭后默认禁止新开考、允许已开考完成（D）。服务端UTC保存，界面Asia/Shanghai显示。

邀请URL使用高熵一次入口token，推荐放fragment，前端移除后以POST换取临时验证上下文；禁止写access log/referrer，Referrer-Policy:no-referrer，候选人页无第三方统计。邮箱验证码仅存哈希，短时有效、限频/限错，无需候选人创建后台账号。持有链接只证明得到链接，邮箱验证也不等于证件级真人核验；本期不声称防替考。

Cookie使用HttpOnly、Secure、SameSite，同域反代避免跨域cookie难题；写请求带CSRF保护，session服务端可撤销。候选人会话绑定attempt和candidate，接口不接受客户端指定其他候选人ID。Redis不可用时鉴权失败关闭，不回退匿名。

一次考次仅一个答卷；start幂等，双设备并发保存用revision返回409，不静默丢失。客户端展示未保存提示；deadline后拒绝新答案，由统一submit动作冻结最后保存答案。beat单实例扫描＋API读/写时惰性超时判定双保险，worker重启后仍能补交，不依赖浏览器开着。

## 7. 账号、隐私和密钥

密码用Argon2id哈希（非可逆加密）。管理员/HR会话服务端存储并支持禁用立即失效。模型/SMTP连接字段允许更新秘密但从不回显原值；密钥采用独立主密钥加密，主密钥不入库、不入Git。首次配置由用户提供，本文不读取/复制已有应用凭据。

后台域、候选人域接口分组和DTO独立。列表/详情/文件/检索/下载/评分均做资源级授权。原文件经授权短期签名URL或代理下载；私有桶禁止公共读取。管理员运维日志只显示任务类型/错误分类/关联ID，不显示简历正文和题目答案。

企业外部候选人访问需正式HTTPS域名、证书、反代与邮件中正确PUBLIC_BASE_URL；本机localhost或内网IP不能给外部人员直接使用。本稿没有发布公网，也不默认开启端口或隧道。

## 8. 环境与交付运行设计

后续采用一份Compose定义Linux服务：api、worker、单实例scheduler、frontend、mysql（或独立外部开发库）、redis、业务minio、milvus及其官方依赖、测试mailpit、nginx。OCR可分独立镜像以隔离Paddle依赖。服务地址使用容器DNS；Windows宿主运行前端时单独覆盖API地址。MySQL已有实例不直接迁移或清空，新库、新账号、最小权限。

开发前冻结实际镜像tag/digest、Python与Node锁文件；所有“latest”仅是发现到的模型标签，不是可重现交付版本。模型以实际digest、embedding维度、上下文、JSON能力验收。不要将所有模型和服务一次塞满本机；31GiB总内存检查时约7GiB空闲，先控制worker并发1、分批OCR，再根据实测调节。

健康检查区分live（进程在）与ready（核心DB/会话可用），依赖状态单列。MySQL/Redis就绪后迁移，种子脚本只生成安全测试账号和业务示例，不写假密钥；模型/邮件不就绪则明确blocked。语义功能验收必须真实Milvus。记录请求request_id、job_id和业务版本链，错误响应不回传raw_error/stacktrace。

备份包括MySQL、私有文件、Milvus配置/索引元信息和加密密钥恢复方案；向量可从MySQL/文件重建。正式数据恢复需在隔离库演练，不能只备份不验证。日志保留期限、备份频率和候选人资料保留策略为上线配置项，不以软删除代替到期清除。

## 9. 主要ADR与旧文档差异

| ADR | 决策建议 | 原因/代价 |
|---|---|---|
| ADR-01 | 单企业模块化单体＋worker，暂不拆全微服务 | 主线事务一致、便于首次联调；需用户接受与旧强制架构不同 |
| ADR-02 | MySQL主库＋Milvus语义索引＋MinIO文件＋Redis任务/会话 | 人才库不是单独向量数据库，向量不存全部业务事实 |
| ADR-03 | 保留LangGraph固定子图，不引入Dify/Vanna/PostgreSQL/Neo4j为一期必需 | 无通用编排、NL2SQL及图谱核心需求；旧“全部强制落地”条款是否取消随本轮技术审阅确认 |
| ADR-04 | Celery仅Linux运行，原生Windows不作为验收环境 | 官方不支持Windows；WSL/Docker须先修复/验证 |
| ADR-05 | 自建正式数据模型，不复用旧seed_data.sql直接灌库 | 旧表缺岗位关系/版本/考次/邀请幂等，旧部分列为推断 |
| ADR-06 | 分数分列、HR决定，模型失败转人工 | 避免把相似度/简历自述变成客观能力或录用结论 |
| ADR-07 | 不预先承诺一次运行成功 | 以环境预检、版本锁定、主线实测与异常恢复最大限度减少返工 |

## 10. 官方核验依据（2026-11-04检索）

- [Next.js安装要求](https://nextjs.org/learn/react-foundations/installation)：当前指南要求Node≥20.9；本机Node文件版本满足数值门槛，但仍需执行与构建验证。
- [Celery支持平台](https://docs.celeryq.dev/en/stable/getting-started/introduction.html)：不支持Windows，因此worker采用Linux。
- [Milvus Windows部署](https://milvus.io/docs/install_standalone-windows.md)：Windows方案需要Docker Desktop/WSL2/Linux容器；实际镜像须与本机2.6.5配置核对，不直接下载不同大版本覆盖。
- [SQLAlchemy同步/异步能力](https://www.sqlalchemy.org/features.html)：支持MySQL及同步/异步；本稿选择同步模式是减少驱动复杂度的设计判断。
- [LangGraph任务与副作用恢复](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/functional-api.mdx)：恢复可能重放，应隔离副作用并实现幂等。
- [PaddleOCR安装](https://www.paddleocr.ai/main/en/version3.x/installation.html)：框架、OCR依赖需分别核对，OCR独立环境是本项目设计选择。
- [Ollama结构化输出](https://ollama.com/blog/structured-outputs)、[API定义](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)：支持schema约束与embedding接口，具体模型能力还需验证。

## 11. 自审后统一约束

共享candidate_profiles及其向量仅包含简历/明确共享资料，岗位考试和面试评价授权后动态附加；不得先把私有评价混入摘要再只隐藏来源。候选人合并采用canonical别名和岗位关系映射，不改写原始版本/考次归属；全部新建关系锁canonical根。开考预建全部题目空答案，未答题提交时记0；复核与finalize同锁串行，正式成绩追加score_reports版本。完成后的评估结果冻结，人工覆盖追加recruitment_events；evaluation_runs.override字段仅用于未完成阶段的工作态摘要，不原位改变已邀考证据。邀请sending仅属notification，取消未发邀请置revoked。
